## 3. html-generator 使用指南

### 3.1 七种文档模式 × 八组调色板（自动选择，可手动指定）

模式：doc（通用文档）/ compare（对比选型）/ status（周报进度）/ explainer（教程讲解）/ dashboard（数据简报）/ deck（品牌长页）/ auto（自由）。
配色：墨蓝、暖金、青绿、玫红、深蓝金、紫韵、橙韵、灰调（如"用深蓝金配色"覆盖）。

### 3.2 转换保真度预期

| 格式 | 语义保真 | 视觉保真 |
|------|---------|---------|
| HTML → Word | 95% | 70%（卡片/时间线降级为表格/段落） |
| HTML → PDF | 95% | 95%（近乎 1:1） |
| HTML → Markdown | 90% | 视觉不保留（预期行为） |

## 4. knowledge-handbook-builder 使用指南

### 4.0 调研深度广度与置信度保证

**广度靠"扫描矩阵强制"，深度靠"证据分级 + 五问闭环"，偏科靠"coverage 可查"，置信度靠"色标可视化"。**

| 机制 | 内容 | 保证什么 |
|------|------|----------|
| 广度扫描矩阵 | Phase 1 每轮先过表：知识类型、产业链节点、替代/竞品、标准法规、来源多样（≥2 类） | 广度不靠自觉 |
| 证据分级 | A级=标准原文/官方/检测报告（单源可写）；B级=行业报告/工厂案例（**需不同渠道双源**）；C级=转述/论坛（必须标"待联网核实"） | 数据可靠性分优先级 |
| 深度五问 | 每个知识块写入前过链：是什么→为什么→依据什么→边界在哪→失效怎样 | 深度不靠写作时才补 |
| 调研产出清单 | Phase 1 结束交付：数据清单/标准清单/知识块清单/待核实项/盲区清单 | 产出可验收 |
| `coverage` 命令 | 四类知识分布 + 产业链粗分，<10% 或 0 提示盲区 | 偏科可量化 |
| **证据级别可视化（v1.4.2）** | res 块标 A绿/B黄/C灰/🔎待核实 色标；不确定项必须标"🔎待核实" | 置信度进成品 |

### 4.1 交付标准（默认全部满足）

- 自包含单文件 HTML（CSS 内联、零外部依赖）
- **SVG 图示**：矢量、不重叠、图号说明、字号≥9.5px；**每个知识点必须配 ≥1 张适合的图示**
- **每个知识点七层结构（基线）**：术语标题 → 通俗解释 → 五维深度解读 → 推荐书籍 → B站视频搜索指引
- **可选维池（v1.3）**：五维基线之上按需取 0-2 个（成本 / 对比 / 反直觉 / 案例）
- 知识体系有逻辑：通用基础 → 品类篇章 → 综合实战
- 双 class 语义标记，可一键转 Word/PDF/Markdown

### 4.2 工具命令速查（Python 3.8+ 零依赖，共 13 个命令）

```bash
python scripts/handbook_tools.py validate  <手册.html>            # 结构验证（6项；dim 区间 [5k,7k]）
python scripts/handbook_tools.py lint      <手册.html> [--strict]  # 内容质量校验（基线五维+可选维0-2+S1-S9）
python scripts/handbook_tools.py stats     <手册.html>            # 快速统计
python scripts/handbook_tools.py anchors   <手册.html>            # 列出知识点锚点
python scripts/handbook_tools.py dupres    <手册.html>            # 书名重复/前缀冲突预警
python scripts/handbook_tools.py dedup     <手册.html> [--apply]  # 重复块检测/删除
python scripts/handbook_tools.py replace   <手册.html> --old "锚点" --new "新内容" --expect 1
python scripts/handbook_tools.py replace   <手册.html> --old-file a.txt --new-file b.txt
python scripts/handbook_tools.py glossary  <手册.html>            # 术语表：kp-term 去重
python scripts/handbook_tools.py quiz      <手册.html>            # 考点卡片：标准号/数字/类比/扩展名词
python scripts/handbook_tools.py crossref  <手册.html>            # 相关知识点：共享书籍/B站词
python scripts/handbook_tools.py path      <手册.html>            # 学习路径：基础→进阶→实战
python scripts/handbook_tools.py coverage  <手册.html>            # 类型分布/偏科告警/产业链盲区
python scripts/handbook_tools.py termcheck <手册.html>            # 术语一致性：term包含/标准型缺标准号/标准号清单
```

**退出码语义**：0=成功；1=验证/检查发现问题（validate=FAIL 必须修复；lint=WARN 质量警告）；2=锚点未找到；3=锚点出现次数与预期不符。

### 4.3 lint 会查什么

| 检查项 | 说明 |
|--------|------|
| 基线五维齐全 | 每个知识点必须恰好含 暗含假设/第一性原理/专业解读/形象化/扩展 各一次 |
| 可选维 0-2 合法 | cost/compare/counterintuition/case 每维≤1次、合计≤2个 |
| 内容长度 | 每维≥10字；通俗解释≥30字 |
| 资源块 | 必须含书籍《》与B站指引 |
| 图号配对 | SVG 数与图号说明一一对应 |
| SVG 字号 | ≥9.5px（--min-font-size 可调） |

**交付标准：validate + lint 双绿。**

### 4.3b --strict 深度质检（S1-S9）

| 规则 | 检查 | 级别 |
|------|------|------|
| S1 | 暗含假设维必须有条件表述（——/若/时/当/一旦） | 硬伤 |
| S2 | 第一性原理维鼓励量化锚（∝/=/次方/定律名/守恒） | SUGGEST |
| S3 | 专业解读维必须有工程锚点（数字/标准号；管理型可用方法论名词） | 硬伤 |
| S4 | 形象化维必须有类比引导词（像/好比/相当于/如同/想象） | 硬伤 |
| S5 | 形象化维与通俗解释的类比不得重复（≥10字公共片段） | 硬伤 |
| S6 | 单维长度上限 150 字 | 硬伤 |
| S7 | kp 图示覆盖率 ≥80%（每 kp≥1 图） | SUGGEST |
| S8 | 知识类型自动判定（工艺/标准/管理/概念，提醒重点维写法） | SUGGEST |
| **S9（v1.4.2）** | **同标准号跨 kp 数值对账**：同一标准号被多个 kp 引用时，同单位数字不一致 → 提示 | SUGGEST |

### 4.4 内容增值四命令（v1.4）

| 命令 | 输出 | 用法建议 |
|------|------|----------|
| `glossary` | 全部知识点术语去重列表 | 整理成手册附录"术语表" |
| `quiz` | 每 kp 考点卡片（标准号/关键数字/原理锚/类比素材/扩展名词） | 交给 LLM 生成选择题/判断题 |
| `crossref` | 共享书籍/B站词的 kp 对 | 在 kp 间加互链 |
| `path` | 按篇章层级输出学习路径 | 写入手册目录导读 |

### 4.5 可选维池（v1.3）

| 可选维 | 类名 | 回答读者 | 示例 |
|--------|------|----------|------|
| 成本 / 代价 | `cost` | 得到它要付出什么 | `材料占60%——批量排产降本` |
| 对比 / 横向 | `compare` | 和同类差在哪 | `A 强度高30%但贵2倍——性能优先选A` |
| 反直觉 / 误区 | `counterintuition` | 直觉哪里骗了我 | `直觉越厚越结实——实际蜂窝结构更轻` |
| 案例 / 证据 | `case` | 有没有真实例子 | `某厂导入共模化，模具成本降22%` |

### 4.6 手册转 Word/PDF/Markdown

模板已挂 html-generator 语义标记。对生成手册说"转 Word/转 PDF/转 Markdown"即可走 html-generator 转换管线。

## 6. FAQ

**Q1: 转 Word 后卡片/渐变没了？**
预期降级（视觉保真约70%），要近乎1:1请转 PDF。

**Q2: 智能体说"Could not find oldString"但内容明明存在？**
已知行尾/跨行问题。用 handbook_tools.py 的 replace（自动兼容 LF/CRLF）。

**Q3: 为什么有的书名不能直接做锚点？**
书名前缀匹配会误插（dupres 命令自动预警）。

**Q4: 手册改完怎么确认没改坏、没写差？**
双重验收：validate（结构）+ lint（内容质量），双绿才交付。

**Q5: 想给知识点加"成本/案例"分析，会不会破坏五维？**
不会。可选维池是独立增强：五维基线必须齐全，可选维按需 0-2 个，lint 自动校验不超载。

**Q6: 怎么知道手册调研有没有漏方向？**
`coverage` 命令：四类知识分布与产业链节点，任一类型 <10% 或为 0、上下游缺失都会提示"疑似盲区"。

**Q7: 读者怎么知道手册里哪句话可靠哪句待核实？（v1.4.2）**
证据级别色标：res 块里 A级=绿、B级=黄、C级=灰、🔎待核实=红。不确定数据必须标"🔎待核实"。

**Q8: 手册里同一个标准号的数字前后矛盾怎么办？（v1.4.2）**
`lint --strict` 的 S9 会自动对账：同一标准号被多个 kp 引用时，同单位数字不一致会提示（如 40mm vs 45mm）。
