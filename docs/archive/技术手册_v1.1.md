## 2. html-generator 技术架构（v1.0 已详述，此处摘要）

### 2.1 转换脚本四层拆分

`sem_common.py`（公共语义识别，三脚本共用）→ `docx_utils.py`（Word OXML 工具）→ `core/enhanced/scene/advanced` 四处理层（6+4+5+10 种 IR）→ `html2docx.py` 主入口分发器；`html2md.py`/`impact_analyzer.py` 仅依赖 sem_common；`html2pdf.py` 独立零依赖；`chart_validator.py` 图表数学校验。修改指引：语义识别改 sem_common（一处修改三脚本同步生效），各 IR 处理按模块职责表定位。

### 2.2 语义 IR 体系

12 块级 + 2 辅助语义 class → 25 种 IR 映射到 Word/PDF/Markdown（映射全部内置脚本，禁止调用方手写）。`chart_unknown` 三层降级：Playwright 截图 → SVG 文本提取重建表格 → 跳过。

## 3. knowledge-handbook-builder 技术架构（v1.1 重点）

### 3.1 单源结构（解决双头维护）

`references/workflow.md` 是**核心流程唯一源**（交付标准/五阶段/命令速查/增量增强/编辑铁律/验证清单）。SKILL.md（TeleAgent）与 AGENT.md（通用智能体）只保留平台差异（触发/接入方式），共同内容全部引用 workflow.md —— 修改流程只改一处，双入口自动同步。

### 3.2 handbook_tools.py 命令规范（v1.1 扩展 lint）

| 命令 | 功能 | 退出码 |
|------|------|--------|
| validate | 结构6项：div平衡/资源覆盖/deep统计/重复检测/图号/闭合 | 0=PASS / 1=FAIL |
| **lint（新）** | 内容质量6项：deep五维各恰好1次/dim≥10字/explain≥30字/res含书籍与B站/svg-图号配对/SVG字号≥9.5 | 0=PASS / 1=WARN |
| stats / anchors / dupres / dedup[--apply] / replace[--expect] | 见 v1.0 | 同前 |

**识别层全面 token 化（v1.1）**：`is_kp_line/is_deep_line/TERM_RE/RES_RE/deep 统计` 从字符串前缀匹配升级为 **class 列表分词匹配**（`class="kp card"`、`class="deep callout"`、`kp-term heading"` 均正确识别；单 class 向后兼容）——这是支撑双 class 互操作的基础。

### 3.3 双 class 语义互操作（v1.1 核心新增）

模板在原有样式类上追加 html-generator 语义类，映射规范：

| 原类 | 语义类 | 转换效果 |
|------|--------|----------|
| body | `mode-doc` + `data-palette="ink-blue"` | 模式/调色板识别依据 |
| .cover | `title` | Word 居中+shading / PDF 新起一页 |
| .category h2 / .block-title / .kp-term | `heading` data-level=1/2/3 | Heading 1/2/3 |
| .kp | `card` data-variant="kp" | 无边框表格+卡片shading |
| .kp-explain | `paragraph` | Body 段落 |
| .deep / .res | `callout` data-variant | 底色+左边框段落 |
| .tip/.warn/.danger | `callout` data-variant=tip/warning | 提示块 |
| table | `table` | Word Table / MD 表格 |
| footer | `end_page` | 新起一页结语 |
| .fig（含svg） | 不加类 | chart_unknown 三层降级（截图/提取/跳过） |

语义类**无需定义CSS样式**（视觉由原类负责，转换器只识别 class 名）。既有未打通的手册仍可转换（兜底为段落）。

### 3.4 lint 实战战果（质量闸门的价值证明）

首次对存量手册（95 kp / 50 svg）运行 lint 即发现 **54 处真实问题**：
- 3 处 res 的 `<span class="book"></span>` 为空 —— 根因是6轮编辑前批量脚本的 PowerShell 参数绑定缺陷（`D $dim + $b` 无括号调用，书名参数被静默丢弃），validate 查不出（结构完好），lint 按资源内容规则逮住；
- 51 处 SVG font-size=8/9 低于 9.5px 规范 —— 全部修复。

修复后 validate+lint 双 PASS。该案例已写入 `references/editing-safety.md`。

## 4. 测试与 CI（v1.1 新增）

### 4.1 测试套件（18 用例，pytest，全部通过）

覆盖：validate 四态（通过/div失衡/资源缺失/重复deep）+ 模板资产回归；replace 三态防护（成功/未找到 exit2 且文件不变/多匹配 exit3 拒绝）+ CRLF 兼容（行尾保持）+ 文件通道；dedup 两段（dry-run 报告→apply 删除后 validate PASS）；dupres 同名书检出；anchors 双class识别；lint 四规则（通过/缺维/空书/小字号，其中空书用例**复现真实缺陷场景**）。

### 4.2 CI（GitHub Actions）

- 矩阵：Python 3.9/3.10/3.11/3.12 × ubuntu-latest
- 步骤：pytest 18用例 → 模板资产 lint（占位符 WARN 属预期，仅提示）→ 模板 validate（必须 PASS）→ 两个 SKILL.md frontmatter YAML 校验（name/description/name_cn/description_cn 必填）

### 4.3 安全扫描

两技能均通过主机安全扫描（0 高风险 / 0 中风险）；本技能目录及手册模板均不含可执行恶意逻辑，工具只读/原子写回设计。

## 5. 编辑安全工程（两技能共享，v1.1 补充）

在 v1.0 五条铁律（锚点先验证/唯一性三规则/长内容文件通道/行尾兼容/报错≠零改动）之上新增：

6. **lint 作为第二道闸**：结构验证（validate）之后必须再跑内容质量（lint）——结构完好≠内容完好（空书名案例）。
7. **批量脚本调用必须用括号**：PowerShell 中 `D $dims + $book` 会被解析为单参数调用（`+`/`$book` 进入 $args 被静默丢弃），必须写 `(D $dims) + $book` ——该缺陷曾致 3 处书名丢失且 6 轮未被发现。
