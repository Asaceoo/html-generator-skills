## 1. 架构总览

转换侧采用**四层拆分 + 公共语义层**结构，三份转换脚本（docx / md / impact）共用同一份语义识别逻辑，避免重复维护。

```
                    sem_common.py（公共语义识别层）
                    SEMANTIC_CLASSES / classify_element / flatten_semantic_blocks
                       │                │                    │
                 html2md.py      impact_analyzer.py      （语义消费方）
                                        │
                    docx_utils.py（Word OXML 工具层 + 图表产出计数器）
                       │
        ┌──────────────┼──────────────┬──────────────┐
   html2docx_core  html2docx_enhanced html2docx_scene html2docx_advanced
     （核心 IR）      （增强 IR）        （场景 IR）      （高级 IR）
        └──────────────┴──────────────┴──────────────┘
                                 │
                        html2docx.py（主入口 + 25 IR 分发器）

html2pdf.py —— 独立，不依赖上述任何模块（Playwright 直出 PDF）
chart_validator.py —— 独立，SVG 图表数学校验
```

## 2. 语义识别：从 class 到 IR

| 层 | 职责 | 关键函数 |
|---|---|---|
| sem_common | 定义 `SEMANTIC_CLASSES`（12 块级 + cite / source-list 辅助），单元素归类与块切分 | `classify_element`、`flatten_semantic_blocks`、`parse_table_data`、`parse_style_blocks` |
| html2docx | 创建 Document、设全局样式、遍历块、按 IR 分发、转换后校验 | `convert_html_to_docx`、`process_block` |
| html2md | Markdown 渲染（结构保真，视觉不保留） | `render_block` |
| impact_analyzer | 转换前降级清单（Word / PDF 报视觉 + 结构，Markdown 只报结构） | `analyze_html` |

**12 种块级语义 class**：title、heading、paragraph、card、table、timeline、stat、code、callout、image、list、end_page。
**辅助**：`cite`（段落内联上标引用）、`source-list`（来源列表容器，内部 `ol.list` 已按列表处理）。
**可选 data-* 属性**：`data-level`、`data-variant`、`data-cols`、`data-lang`、`data-caption`、`data-float`、`data-layout`。

未加语义 class 的元素按结构特征兜底识别：`<blockquote>`→quote、`Q:` 开头 / `<details>`→faq、badge/tag 类名→badge_group、多图网格→gallery、icon+文字→icon_list、短线+菱形→divider、含 svg/canvas 或无文本容器→chart_unknown。

## 3. 关键机制

### 3.1 转换后双校验（防静默丢内容）

| 校验 | 口径 | 触发 |
|---|---|---|
| 文本量比对 | HTML 可见文本（排除 style/script/截图容器）vs Word 段落 + 表格文本 | 差异 > 15% → WARNING；> 20% → ERROR 级提示 |
| 图表容器核对 | `.funnel-stage` / `.bar-row` / `.bar > .bar-val` 的文本必须能在 Word 中子串命中 | 任一容器找不到 → WARNING |
| 图表产出对账（v1.9.0 新增） | HTML 中 SVG/Canvas 图表宿主数（同一容器内多个 svg 合并计 1）减去"纯装饰跳过数"，与转换端实际产出数（截图 + 重建）比对 | 期望 > 产出 → WARNING |

图表产出对账的计数来自 `docx_utils.CHART_RENDER_STATS`，由 `html2docx_scene.py` 在截图成功 / 数据重建 / 装饰跳过时调用 `bump_chart_stat()` 递增；每次转换开始由 `reset_chart_stats()` 清零。

> 背景：原先只有前两项校验，SVG 图表（当前最主流的图表形式）完全不在核对范围内，会打印"0 个图表容器全部找回"，形成核对盲区与误导性 INFO。

### 3.2 chart_unknown 三层降级

1. **第 0 层**：Playwright 光栅化该元素区域 → PNG 插入 Word（视觉保真最高）
2. **第 1 层**：递归提取 SVG 文本与数据属性 → 重建表格（多列）或列表（单列）
3. **第 2 层**：零文本零数据（纯装饰）→ 跳过，并计入 `skipped`（不产生误报）

### 3.3 输出编码策略（v1.9.0 修复）

原实现无条件 `sys.stdout.reconfigure(encoding='utf-8')`。Windows 下宿主控制台按系统 ANSI（GBK/cp936）解码子进程 stdout，UTF-8 字节被按 GBK 解码 → 中文乱码，读取降级清单的一方（AI / 日志管道）拿到不可解析字符串。

现策略：仅当默认编码属于"注定无法表达中文"的集合（ascii / us-ascii / cp1252 / latin-1 / 空）时才切 UTF-8，GBK / UTF-8 原样保留。入口脚本 `convert.ps1` 同步改为沿用宿主代码页设置 `PYTHONIOENCODING`。

### 3.4 Python 环境管理

`convert.ps1`（Windows）优先级：conda env `html-convert` → venv `~/.html-convert-env`。
conda 环境创建失败时（离线 / 镜像源问题）会写入标记 `~/.html-convert-env/.conda_create_failed`，此后直接走 venv，避免每次转换空等 30s+。删除该标记可恢复 conda 尝试。

依赖：`python-docx`、`beautifulsoup4`、`lxml`、`playwright`（含 Chromium）；可选 `pymupdf`（PDF 尾页空白检测）、`cssutils`（`<style>` 预解析），缺失自动降级。

## 4. 修改指南

**新增一种 IR 语义**

1. `sem_common.py` → `classify_element` 加识别规则
2. `sem_common.py` → `flatten_semantic_blocks` 加聚合 / 分块逻辑（如需）
3. 对应处理层文件加 `process_xxx`
4. `html2docx.py` → `process_block` 加 `elif` 分支
5. `html2md.py` → `render_block` 的 handlers 加渲染函数
6. `impact_analyzer.py` → 降级说明表加条目

**改语义识别**：只改 `sem_common.py`，三份脚本同步生效。
**改 Word OXML 操作**：只改 `docx_utils.py`。
**改某一类块**：只改对应层（core / enhanced / scene / advanced）。

> 硬性约束：禁止另行编写转换脚本替代内置脚本。内置脚本对折叠卡片、指标卡、时间线等 25 种 IR 有专门处理，手写脚本会大量丢内容（历史上发生过折叠卡内 12 条详情全部丢失的事故）。

## 5. 测试与真机验证

### 5.1 冒烟夹具

仓库无内置 fixture 时，可用最小覆盖用例自测：一份包含 12 种块级语义 + cite/source-list + SVG 饼图的 HTML，依次跑：

```bash
python scripts/chart_validator.py fixture.html
python scripts/impact_analyzer.py fixture.html --format docx --json
python scripts/html2docx.py fixture.html out.docx
python scripts/html2md.py   fixture.html out.md
python scripts/html2pdf.py  fixture.html out.pdf
```

### 5.2 本轮真机验证结果（Windows 11 / Python 3.12 venv / Playwright Chromium）

| 用例 | 结果 |
|---|---|
| 7 个模式骨架 → Word（骨架含未替换占位符） | 全部通过，无崩溃，文本差异 -13.6% ~ +6.5% |
| 全语义 fixture → Word | 通过；chart_unknown 截图插入；文本差异 0.7% |
| 全语义 fixture → Markdown / PDF | 通过；PDF 提示 pymupdf 缺失（已补入 requirements 可选段） |
| 空 body / 未闭合标签 / 无语义 class / 含 script / 16 列宽表 | 全部通过，无异常，文本量 100% 保留 |
| 交互组件（Tab 组 / 折叠组 / `<details>`）→ docx / md / pdf | 通过：Tab 两面板与折叠标题 + 正文全部展开保留；PDF 提示"展开 1 个 details"。过程中发现并修复了 Markdown 侧 `<summary>` 标题被丢弃的问题 |
| Windows 入口脚本 docx / md | 通过；跳过 conda 后耗时约 37s（含 Chromium 启动） |
| `py_compile` 全部脚本 | 通过 |
| CI 等价 frontmatter 校验 | 两个 SKILL.md 的 name/description/name_cn/description_cn 齐全 |

## 6. 发布流程

```bash
python scripts/release.py --part minor     # patch / minor / major，默认 patch
```

按顺序执行：读 `VERSION` → 递增 → 回写并同步 `html-generator/VERSION` 与 `knowledge-handbook-builder/VERSION` → 旧版手册复制进 `docs/archive/` → 生成新版手册（内容中版本号整体替换 + 文件重命名）→ 打包 `dist/html-generator-vX.Y.Z.zip`（排除 `__pycache__` / `.pyc` / `dist`）。

可选参数：`--no-bump`（只重打包）、`--no-zip`（只递增同步）、`--skill`（指定打包的技能目录）。

发版后再更新 `CHANGELOG.md`，并把 zip 作为 Release 附件上传。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| Word 视觉保真约 70% | 渐变 / 圆角 / 阴影 / 定位 / 动画按 Word 文档模型限制丢失 |
| 图表核对仍存在残余盲区 | 若图表截图失败且无数据可提取，会被判为"纯装饰跳过"而不告警；此时日志会打印截图不可用信息 |
| GitHub Actions 未覆盖 html-generator 转换回归 | 现有 CI 只跑 `knowledge-handbook-builder` 的 pytest 与两个 SKILL.md frontmatter 校验 |
| Playwright 首次安装约 100MB | 离线环境需预置 Chromium |
| 超宽表格（> 8 列） | Word / PDF 可读性下降，生成端建议按季度合并时间维度 |
