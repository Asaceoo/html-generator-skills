## 1. 这套技能能帮你做什么

| 你想做的事 | 用哪个技能 | 一句话说明 |
|------------|-----------|-----------|
| 生成一份漂亮的报告/方案/周报，并一键转 Word/PDF/Markdown | **html-generator** | 一次内容编排，四种格式输出 |
| 深度调研一个领域，沉淀成带图示的 HTML 知识手册 | **knowledge-handbook-builder** | 调研 → 体系 → 手册，持续迭代增强 |
| **把已生成的知识手册再转成 Word / PDF / Markdown** | **knowledge手册（v1.1 新）** | 手册模板已挂语义标记，对 html-generator 说"转 Word"即可 |
| 给既有大型手册"继续加内容"而不重做 | **knowledge-handbook-builder**（编辑模式） | 锚点验证 + 批量插入 + 自动验证 |
| 生成带图表的数据简报 | **html-generator** | 图表坐标程序计算 + 数学校验 + 视觉复核 |
| **在交付前自动查内容质量**（五维缺失/书名丢失/字号过小） | **handbook_tools lint（v1.1 新）** | 一条命令查出书名丢失等隐性问题 |
| 把两个技能给其他 AI 智能体（WorkBuddy 等）使用 | 见 §5 接入指南 | 提示词 / 命令行 / MCP 三种方式 |

## 3. html-generator 使用指南

### 3.1 七种文档模式 × 八组调色板（自动选择，可手动指定）

模式：doc（通用文档）/ compare（对比选型）/ status（周报进度）/ explainer（教程讲解）/ dashboard（数据简报）/ deck（品牌长页）/ auto（自由）。
配色：墨蓝、暖金、青绿、玫红、深蓝金、紫韵、橙韵、灰调（如"用深蓝金配色"覆盖）。

### 3.2 转换保真度预期

| 格式 | 语义保真 | 视觉保真 |
|------|---------|---------|
| HTML → Word | 95% | 70%（卡片/时间线降级为表格/段落） |
| HTML → PDF | 95% | 95%（近乎 1:1） |
| HTML → Markdown | 90% | 视觉不保留（预期行为） |

### 3.3 图表质量三保障

坐标程序计算 → chart_validator.py 数学校验（角度总和/颜色一致/数据对应）→ 截图+视觉模型复核。

## 4. knowledge-handbook-builder 使用指南

### 4.1 交付标准（默认全部满足）

自包含单文件 HTML；SVG 图示（矢量/不重叠/图号说明/≥9.5px 字号/按需三维视角）；每个知识点七层结构（术语→通俗解释→五维深度解读→书籍→B站视频）；体系有逻辑（通用基础→品类→综合实战）。

### 4.2 工具命令速查（Python 3.8+ 零依赖）

```bash
python scripts/handbook_tools.py validate  <手册.html>            # 结构验证（6项）
python scripts/handbook_tools.py lint      <手册.html>            # 内容质量校验（v1.1新增）
python scripts/handbook_tools.py stats     <手册.html>            # 快速统计
python scripts/handbook_tools.py anchors   <手册.html>            # 列出知识点锚点
python scripts/handbook_tools.py dupres    <手册.html>            # 书名重复/前缀冲突预警
python scripts/handbook_tools.py dedup     <手册.html> [--apply]  # 重复块检测/删除
python scripts/handbook_tools.py replace   <手册.html> --old "锚点" --new "新内容" --expect 1
python scripts/handbook_tools.py replace   <手册.html> --old-file a.txt --new-file b.txt
```

### 4.3 lint 会查什么（v1.1 新）

| 检查项 | 说明 |
|--------|------|
| deep 五维齐全 | 每个知识点的深度解读必须恰好含暗含假设/第一性原理/专业解读/形象化/扩展各一次 |
| 内容长度 | 每维≥10字；通俗解释≥30字 |
| 资源块 | 必须含书籍《》与B站指引（曾逮住3处批量脚本缺陷导致的书名丢失） |
| 图号配对 | SVG 数与图号说明一一对应 |
| SVG 字号 | ≥9.5px（--min-font-size 可调） |

**交付标准：validate + lint 双绿。**

### 4.4 手册转 Word/PDF/Markdown（v1.1 新）

模板已挂 html-generator 语义标记（kp→card、deep/res→callout、标题→heading、表格→table）。对生成手册说"转 Word/转 PDF/转 Markdown"即可走 html-generator 转换管线：kp 转无边框表格卡片、深度解读转底色边框段落、SVG 图示自动截图插入 Word。

## 6. FAQ

**Q1: 转 Word 后卡片/渐变没了？**
预期降级（视觉保真约70%），转换前会做影响分析并告知确认。要近乎1:1请转 PDF。

**Q2: 智能体说"Could not find oldString"但内容明明存在？**
已知行尾/跨行问题。用 handbook_tools.py 的 replace（自动兼容 LF/CRLF），不要用普通编辑工具硬改。

**Q3: 为什么有的书名不能直接做锚点？**
书名前缀匹配会误插（dupres 命令自动预警同名与前缀冲突）。

**Q4: 手册改完怎么确认没改坏、没写差？**
v1.1 起是**双重验收**：validate（结构：div平衡/资源覆盖/deep统计/图号/闭合）+ lint（内容质量：五维齐全/字数/资源/字号），双绿才交付。

**Q5: 两个技能是什么关系？**
html-generator 负责"单篇文档生成与格式转换"；knowledge-handbook-builder 负责"多轮调研沉淀成可长期迭代的知识手册"。**v1.1 起两者已打通**：手册模板带语义标记，可无缝进入 html-generator 的转换管线。
