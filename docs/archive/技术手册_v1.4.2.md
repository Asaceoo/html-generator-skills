## 4. lint 双模式与类型判定（v1.4.2 更新）

```python
BASELINE_DIMS = ("assumption", "principle", "pro", "vivid", "ext")   # 必须各恰 1 次
OPTIONAL_DIMS = ("cost", "compare", "counterintuition", "case")      # 每维≤1、合计≤2
```

**S1-S9 规则**（S1-S8 见 v1.4 技术手册；v1.4.2 变更）：

| 规则 | 变更 | 说明 |
|------|------|------|
| **S8 权重修正** | 标准语义词 `+2 → +3` | 修复平局偏置：`max(score, key=score.get)` 平局时取 dict 先序（工艺型优先）。kp 含 标准/偏差/测量点 多标准词但仅工艺弱词（厚度）时，旧权重 2:2 平局误判工艺型；+3 后标准型胜出 |
| **S9 新增** | 同标准号跨 kp 数值对账 | 聚合 pro 维 (标准号 → 数值列表)，按单位（mm/%/℃/MPa…）分组，同单位 >1 个不同值 → `[SUGGEST] 标准号 {st} 跨 kp 数值不一致（{u}）：{vals}（涉及：{kps}）` |

**S9 实现要点**：只统计"pro 含标准号"的 kp（无标准号的 kp 数值不参与对账，避免误报）；`±1mm` 提取为 `1mm`（± 被正则忽略，为已知小噪声，不影响冲突检出）。

## 5. 证据级别可视化（v1.4.2 新增）

**模板 CSS**（`handbook-template.html`）：

```css
.ev{display:inline-block;font-size:10.5px;font-weight:700;padding:1px 6px;border-radius:8px;margin-left:6px;vertical-align:1px}
.ev-a{color:#15803d;background:#dcfce7;border:1px solid #bbf7d0}      /* A级 绿 */
.ev-b{color:#a16207;background:#fef9c3;border:1px solid #fef08a}      /* B级 黄 */
.ev-c{color:#6b7280;background:#f3f4f6;border:1px solid #e5e7eb}      /* C级 灰 */
.ev-pending{color:#b91c1c;background:#fee2e2;border:1px solid #fecaca}/* 待核实 红 */
```

用法：`<span class="ev ev-a">A级</span>` / `<span class="ev ev-pending">🔎待核实</span>`，置于 res 块内。规则（html-structure.md §证据级别标注）：不确定项**必须**标"🔎待核实"；Phase 1 检查点展示"待核实项清单（置信度汇总）"。

## 6. Phase 1 调研机制（v1.4.1 + v1.4.2 更新）

| 机制 | 要点 |
|------|------|
| 广度扫描矩阵 | 5 面：类型/产业链/竞品/标准/来源（≥2 类） |
| 证据分级 | A 单源可写；B 需**不同渠道**双源（**v1.4.2 独立性定义**：官方/报告/论文/工厂各取其一，同渠道转述不算独立）；C 标"待联网核实" |
| 深度五问 | 是什么→为什么→依据什么→边界在哪→失效怎样 |
| 调研产出清单 | 数据清单（数值+来源+级别）/标准清单/知识块清单/待核实项/**盲区清单** |
| CHECKPOINT | 展示四项：①数据与来源（含证据级别）②类型/节点覆盖表 ③盲区清单 ④**待核实项清单** |

## 8. 扩展指南

## 9. 质量保障与已知边界

- **真机验证链**：py_compile → 模板 validate PASS → 冲突测试（term 包含 2 对 / 标准型缺标准号 / S9 40mm vs 45mm 对账）→ 回归全部命令
- **已知边界**：单行 HTML 无法识别 kp；Python 与 Git Bash `/tmp` 路径不一致；S9 的 `±` 前缀噪声（`±1mm`→`1mm`）
- **回滚点**：`.extbak-*` 备份；`git checkout` 而非 `git reset --hard`
