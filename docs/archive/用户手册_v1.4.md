## 1. 这套技能能帮你做什么

| 你想做的事 | 用哪个技能 | 一句话说明 |
|------------|-----------|-----------|
| 生成一份漂亮的报告/方案/周报，并一键转 Word/PDF/Markdown | **html-generator** | 一次内容编排，四种格式输出 |
| 深度调研一个领域，沉淀成带图示的 HTML 知识手册 | **knowledge-handbook-builder** | 调研 → 体系 → 手册，持续迭代增强 |

| **把手册变成可自测的学习材料**（术语表/考点/关联/路径） | **handbook_tools 内容增值四命令（v1.4 新）** | glossary / quiz / crossref / path 一条命令各出一样 |

## 3. html-generator 使用指南

### 3.1 七种文档模式 × 八组调色板（自动选择，可手动指定）

模式：doc（通用文档）/ compare（对比选型）/ status（周报进度）/ explainer（教程讲解）/ dashboard（数据简报）/ deck（品牌长页）/ auto（自由）。
配色：墨蓝、暖金、青绿、玫红、深蓝金、紫韵、橙韵、灰调（如"用深蓝金配色"覆盖）。

### 3.2 转换保真度预期

| 格式 | 语义保真 | 视觉保真 |
|------|---------|---------|
| HTML → Word | 95% | 70%（卡片/时间线降级为表格/段落） |
| HTML → PDF | 95% | 95%（近乎 1:1） |
| HTML → Markdown | 90% | 视觉不保留（预期行为） |

## 4. knowledge-handbook-builder 使用指南

### 4.1 交付标准（默认全部满足）

- 自包含单文件 HTML（CSS 内联、零外部依赖）
- **SVG 图示**：矢量、不重叠、图号说明、字号≥9.5px；**每个知识点必须配 ≥1 张适合的图示**（v1.3 硬规则，选型提示词见 svg-guide.md）
- **每个知识点七层结构（基线）**：术语标题 → 通俗解释（含生活化类比）→ 五维深度解读 → 推荐书籍 → B站视频搜索指引
- **可选维池（v1.3）**：五维基线之上按需取 0-2 个（成本 / 对比 / 反直觉 / 案例）
- 知识体系有逻辑：通用基础 → 品类篇章 → 综合实战
- 双 class 语义标记（v1.1 起），可一键转 Word/PDF/Markdown

### 4.2 工具命令速查（Python 3.8+ 零依赖，共 11 个命令）

```bash
python scripts/handbook_tools.py validate  <手册.html>            # 结构验证（6项；dim 区间 [5k,7k]）
python scripts/handbook_tools.py lint      <手册.html> [--strict]  # 内容质量校验（基线五维+可选维0-2）
python scripts/handbook_tools.py stats     <手册.html>            # 快速统计
python scripts/handbook_tools.py anchors   <手册.html>            # 列出知识点锚点
python scripts/handbook_tools.py dupres    <手册.html>            # 书名重复/前缀冲突预警
python scripts/handbook_tools.py dedup     <手册.html> [--apply]  # 重复块检测/删除
python scripts/handbook_tools.py replace   <手册.html> --old "锚点" --new "新内容" --expect 1
python scripts/handbook_tools.py replace   <手册.html> --old-file a.txt --new-file b.txt
# —— 内容增值（v1.4 新）——
python scripts/handbook_tools.py glossary  <手册.html>            # 术语表：kp-term 去重，可作附录
python scripts/handbook_tools.py quiz      <手册.html>            # 考点卡片：标准号/数字/类比/扩展名词
python scripts/handbook_tools.py crossref  <手册.html>            # 相关知识点：共享书籍/B站词的 kp 对
python scripts/handbook_tools.py path      <手册.html>            # 学习路径：基础→进阶→实战
```

**退出码语义**：0=成功；1=验证/检查发现问题（validate=FAIL 必须修复；lint=WARN 质量警告）；2=锚点未找到；3=锚点出现次数与预期不符。

### 4.3 lint 会查什么

| 检查项 | 说明 |
|--------|------|
| 基线五维齐全 | 每个知识点必须恰好含 暗含假设/第一性原理/专业解读/形象化/扩展 各一次 |
| 可选维 0-2 合法 | cost/compare/counterintuition/case 每维≤1次、合计≤2个（v1.3） |
| 内容长度 | 每维≥10字；通俗解释≥30字 |
| 资源块 | 必须含书籍《》与B站指引 |
| 图号配对 | SVG 数与图号说明一一对应 |
| SVG 字号 | ≥9.5px（--min-font-size 可调） |

**交付标准：validate + lint 双绿。**

### 4.3b --strict 深度质检（v1.2 起，v1.3/v1.4 扩展）

| 规则 | 检查 | 级别 |
|------|------|------|
| S1 | 暗含假设维必须有条件表述（——/若/时/当/一旦） | 硬伤 |
| S2 | 第一性原理维鼓励量化锚（∝/=/次方/定律名/守恒） | SUGGEST |
| S3 | 专业解读维必须有工程锚点（数字/标准号；管理型可用方法论名词） | 硬伤 |
| S4 | 形象化维必须有类比引导词（像/好比/相当于/如同/想象） | 硬伤 |
| S5 | 形象化维与通俗解释的类比不得重复（≥10字公共片段） | 硬伤 |
| S6 | 单维长度上限 150 字（五维是密度块不是段落） | 硬伤 |
| S7 | **kp 图示覆盖率 ≥80%**（v1.3 新：每 kp≥1 图） | SUGGEST |
| S8 | **知识类型自动判定**（工艺/标准/管理/概念，提醒重点维写法，v1.4 新） | SUGGEST |

> 新写手册建议 --strict 硬伤为 0；SUGGEST 不计入硬伤。

### 4.4 内容增值四命令（v1.4 新）

| 命令 | 输出 | 用法建议 |
|------|------|----------|
| `glossary` | 全部知识点术语去重列表（含行号/书籍引用） | 整理成手册附录"术语表" |
| `quiz` | 每 kp 考点卡片（标准号/关键数字/原理锚/类比素材/扩展名词） | 交给 LLM 基于素材生成选择题/判断题 |
| `crossref` | 共享书籍/B站词的 kp 对（"相关知识点"建议） | 在 kp 间加互链，形成知识网络 |
| `path` | 按篇章层级输出"基础→进阶→实战"学习路径 | 写入手册目录导读 |

### 4.5 可选维池（v1.3 新）

五维基线之外，按知识点需要取 **0-2 个**可选维（写作四要素见 html-structure.md §可选维池）：

| 可选维 | 类名 | 回答读者 | 示例 |
|--------|------|----------|------|
| 成本 / 代价 | `cost` | 得到它要付出什么 | `材料占60%——批量排产降本` |
| 对比 / 横向 | `compare` | 和同类差在哪 | `A 强度高30%但贵2倍——性能优先选A` |
| 反直觉 / 误区 | `counterintuition` | 直觉哪里骗了我 | `直觉越厚越结实——实际蜂窝结构更轻` |
| 案例 / 证据 | `case` | 有没有真实例子 | `某厂导入共模化，模具成本降22%` |

### 4.6 手册转 Word/PDF/Markdown

模板已挂 html-generator 语义标记（kp→card、deep/res→callout、标题→heading、表格→table）。对生成手册说"转 Word/转 PDF/转 Markdown"即可走 html-generator 转换管线。

## 6. FAQ

**Q1: 转 Word 后卡片/渐变没了？**
预期降级（视觉保真约70%），要近乎1:1请转 PDF。

**Q2: 智能体说"Could not find oldString"但内容明明存在？**
已知行尾/跨行问题。用 handbook_tools.py 的 replace（自动兼容 LF/CRLF），不要用普通编辑工具硬改。

**Q3: 为什么有的书名不能直接做锚点？**
书名前缀匹配会误插（dupres 命令自动预警同名与前缀冲突）。

**Q4: 手册改完怎么确认没改坏、没写差？**
双重验收：validate（结构）+ lint（内容质量），双绿才交付。

**Q5: 我想给知识点加"成本/案例"这类分析，会不会破坏五维？**
不会。可选维池是独立增强（v1.3）：五维基线必须齐全，可选维按需 0-2 个，lint 自动校验不超载；存量五维手册无可选维照常通过。

**Q6: 术语表/考点/学习路径是自动生成的吗？**
是工具提取（v1.4），但考点题目润色与术语分类建议由 LLM 基于输出完成——命令给素材，LLM 出成品。
